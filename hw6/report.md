## 3. Реализация fuzzing для калькулятора

Для метода `calculate` был реализован тест `test_calculate_with_processed_input` в файле `calcPython/fuzz.py`.

Особенности реализации:

- вход генерируется через `Hypothesis` с ограниченным алфавитом арифметических символов, пробелов, букв и служебных знаков;
- каждая случайная строка предварительно обрабатывается методом `opn`;
- исключения из `opn` игнорируются, так как по условию проверять этот метод не требовалось;
- для `calculate` допустимыми считаются только `CalcException`, `OverflowError` и `ValueError`;
- любые другие исключения считаются дефектами и приводят к падению теста.

Использованная команда запуска:

```bash
pytest --hypothesis-show-statistics calcPython/fuzz.py::test_calculate_with_processed_input -q
```

## 4. Найденные ошибки в calculate

### 4.1. Ошибка 1: `IndexError` на пустом выражении

`Hypothesis` быстро нашёл минимальный контрпример: пустая строка `''`.

Причина:

- после обработки токенов стек оставался пустым;
- функция без дополнительных проверок выполняла `stack.pop()`;
- это приводило к `IndexError: pop from empty list`.

Исправление:

- добавлена явная проверка на пустой стек;
- вместо аварийного падения теперь выбрасывается контролируемый `CalcException("Пустое выражение")`.

Лог запуска:

- `artifacts/fuzz_logs/01_calc_bug_empty_expression.txt`

### 4.2. Ошибка 2: `IndexError` при обработке оператора

После исправления пустого выражения следующий прогон выявил падение на выражении `0!0`, которое после `opn` превращалось в `0 0 !`.

Причина:

- оператор хранится в строке длины `1`;
- в `match` использовалось обращение к `s_tmp[1]` вместо `s_tmp[0]`;
- это приводило к `IndexError: string index out of range`.

Исправление:

- обращение к оператору заменено на корректное значение `s_tmp[0]`;
- дальнейшая логика обработки операций стала достижимой.

Лог запуска:

- `artifacts/fuzz_logs/02_calc_bug_operator_indexerror.txt`

### 4.3. Ошибка 3: `NotImplementedError` для оператора `!`

После исправления индекса `Hypothesis` снова нашёл минимальный контрпример `0!0`.

Причина:

- ветка обработки `!` выбрасывала `NotImplementedError`;
- по условию задания это недопустимое исключение и считается реальным багом.

Исправление:

- добавлена функция `apply_factorial`;
- оператор `!` реализован как унарный постфиксный факториал;
- для недопустимых значений (отрицательные, нецелые, бесконечные) выбрасывается `CalcException`.

Лог запуска:

- `artifacts/fuzz_logs/03_calc_bug_notimplemented_factorial.txt`

## 5. Итоговые исправления в calc.py

В финальной версии были внесены следующие изменения:

- добавлена безопасная обработка пустого результата;
- исправлена адресация символа оператора;
- реализован оператор `!`;
- удалён некорректный перехват `CalcException`, который маскировал исходную причину ошибки;
- для недопустимых числовых токенов теперь выбрасывается управляемый `CalcException`;
- обработка `%` синхронизирована между `opn` и `calculate`;
- деление по модулю на ноль теперь приводит к `CalcException`, а не к аварийному исключению;
- в `opn` дополнительно улучшена обработка скобок, чтобы калькулятор корректнее работал и в обычном режиме запуска.

Для проверки были добавлены регрессионные тесты:

- пустое выражение;
- обычная бинарная операция;
- факториал;
- остаток от деления на ноль.

Команда запуска:

```bash
pytest -q calcPython/test_calc_regressions.py
```
