## 3. Найденные ошибки

### 3.1. Авторизация: запрещённый символ в session id удаляется перед отправкой

Раздел спецификации: `1. Сессии и авторизация`.

Условия воспроизведения:

1. Открыть страницу входа.
2. Ввести идентификатор вида `abcd!`, где `!` является запрещённым символом.
3. Нажать `Login`.

Ожидаемое поведение:

- приложение остаётся на форме входа;
- отображается ошибка о недопустимых символах в идентификаторе.

Фактическое поведение:

- клиентский код удаляет запрещённый символ перед запросом;
- вместо `abcd!` на сервер уходит `abcd`;
- вход проходит успешно, хотя исходный идентификатор был некорректным.

Автотест: `идентификатор с запрещенным символом не должен проходить авторизацию`.

### 3.2. Авторизация: идентификатор длиной 20 символов отвергается

Раздел спецификации: `1. Сессии и авторизация`.

Условия воспроизведения:

1. Открыть страницу входа.
2. Ввести session id из 20 латинских букв/цифр.
3. Нажать `Login`.

Ожидаемое поведение:

- идентификатор принимается как корректный, потому что спецификация разрешает длину от 4 до 20 символов включительно;
- пользователь входит в приложение.

Фактическое поведение:

- приложение показывает ошибку `Идентефикатор сессии слишком короткий или длинный`;
- сессия длиной ровно 20 символов не создаётся.

Автотест: `идентификатор длиной 20 символов должен считаться корректным`.

### 3.3. Перемещение: позиция меняется до завершения таймера

Раздел спецификации: `2. Описание модели и режима перемещения`.

Условия воспроизведения:

1. Создать сессию.
2. Запросить перемещение вправо.
3. Сразу после запроса проверить координату корабля.

Ожидаемое поведение:

- перемещение на одну клетку занимает не менее 1 секунды;
- до завершения таймера координата корабля не меняется.

Фактическое поведение:

- сервер меняет позицию сразу после запроса на перемещение;
- координата становится новой без ожидания секунды.

Автотест: `перемещение на соседнюю клетку не должно применяться раньше завершения секундного таймера`.

### 3.4. Торговля: цена отображается в обратном порядке

Раздел спецификации: `3. Описание режима торговли`.

Условия воспроизведения:

1. Войти в порт.
2. Открыть таблицу торговли.
3. Посмотреть колонку `Цена (Купить/Продать)` для товара.

Ожидаемое поведение:

- в колонке сначала отображается цена покупки, затем цена продажи: `Купить/Продать`.

Фактическое поведение:

- интерфейс выводит цену в обратном порядке: `Продать/Купить`;
- например для товара с `buyPrice = 16.50` и `sellPrice = 13.50` в таблице показано `13.50/16.50`.

Автотест: `колонка цены должна показывать стоимость в порядке Купить/Продать`.

### 3.5. Торговля: нулевое количество товара помечается как допустимая операция

Раздел спецификации: `3. Описание режима торговли`.

Условия воспроизведения:

1. Войти в порт.
2. В поле покупки товара ввести `0`.
3. Проверить цвет кнопки покупки.

Ожидаемое поведение:

- операция с нулевым количеством недопустима;
- кнопка должна быть красной.

Фактическое поведение:

- кнопка остаётся зелёной;
- интерфейс показывает нулевую покупку как допустимую, хотя спецификация требует положительное количество товара.

Автотест: `нулевое количество товара является недопустимой покупкой и должно помечать кнопку красной`.

## 4. Автоматизированные тесты

Тесты написаны на Playwright. Они проверяют требования спецификации, а не текущее ошибочное поведение, поэтому на переданном приложении должны завершаться падением.

Команда запуска:

```bash
cd hw8
npm install
npm test
```

Если браузеры Playwright ещё не установлены на машине:

```bash
npx playwright install chromium
```

Сервер можно запускать отдельно:

```bash
java -jar tradingboatmodel-0.2.1-SNAPSHOT.jar
```

Также в `playwright.config.js` настроен `webServer`, поэтому при свободном порте Playwright может поднять сервер сам. Если сервер уже работает на `localhost:8091`, будет использован существующий процесс.
